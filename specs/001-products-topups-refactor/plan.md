# Implementation Plan: Products & Top-Up Management Refactor

**Branch**: `001-products-topups-refactor` | **Date**: 2026-04-15 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-products-topups-refactor/spec.md`

---

## Summary

Migrate all admin Products and Top-Up management pages (List, Create, Edit — 6 pages total)
from raw `useState`/`useEffect` data-fetching to TanStack React Query (`useQuery` + `useMutation`).
Every write operation fires `authService.clearCache()` then `queryClient.invalidateQueries`.
A new `adminDeleteTag` method is added to `catalogService`. Tag inline management (create +
delete) on Product forms is fully wired with correct query invalidation and stale-time rules.

---

| ID | Decision |

| R-06 | Products list uses server-side `product_type` exclusion; verify exact param at impl time |

## Phase 1 — Design & Contracts

**Outputs**:
- [data-model.md](./data-model.md) — entities, validation rules, state transitions, mutation→invalidation map
- [contracts/api-contracts.md](./contracts/api-contracts.md) — 11 endpoint contracts (C-01 to C-11)

**Key design decisions**:
- Pages are **thin orchestrators**: they compose custom hooks and existing UI components — no business logic lives in `page.tsx` files.
- All data logic is extracted into `src/hooks/admin/` for reuse across Create + Edit surfaces.
- `useCacheClear.ts` is the single enforcer of the `clearCache() → invalidateQueries` contract.
- Tag deletion triggered from `ProductTags.tsx` — only component that needs UI surgery in this phase.
